# GuideGlass AI 0.2 — إعادة بناء مكانية فعلية

تطوير لملفات GuideGlass الأصلية، لا مشروع واجهة بديل. يستقبل صورًا حقيقية ويحوّل العمق إلى نقاط ثلاثية الأبعاد، يتتبع الكاميرا، ويدمج النقاط المقبولة في خريطة قابلة للحفظ.

**نسخة بحثية غير صالحة للملاحة أو عبور الشوارع. عمق الكاميرا العادية تقديري وليس مسح LiDAR.**

## شغّله الآن على هذا الكمبيوتر

النسخة المعدّلة داخل:

`C:\Users\G I G A B Y T E\Downloads\GuideGlass_Windows_iPhone_v01 (3)\GuideGlass_Windows_iPhone_v01`

1. افتح `start_windows.bat`. الاعتماديات والنماذج وتسجيل الاختبار مثبتة بالفعل في هذا المجلد.
2. على Windows افتح `http://127.0.0.1:8766/`.
3. على iPhone المتصل بنفس Wi-Fi افتح عنوان Windows الذي يطبعه الخادم، مثل `http://192.168.18.11:8766/`. العنوان قد يتغير؛ لا تستخدم localhost على الهاتف.
4. اختر **تسجيل Kinect حقيقي — RGB-D** واضغط **بدء مسح جديد**. يرتفع عدد النقاط والإطارات أثناء المعالجة. اسحب المشهد للدوران واستخدم إصبعين للتقريب، أو اضغط **إظهار الكل**.
5. اضغط **حفظ الخريطة**، ثم أوقف المسح واختر الخريطة واضغط **فتح الخريطة**. تنزيل PLY يحفظ النقاط الملونة، وليس صورة.
6. لتجربة AI اختر **نفس التسجيل — تقدير العمق بالذكاء الاصطناعي**، أو اختر فيديو MP4/MOV من جهازك. لا تستورد قراءة الحساس في وضع RGB-only.
7. استخدم **تفعيل الصوت وتجربته** لطلب النطق. اللغة والصوت والسرعة قابلة للتغيير.

المنفذ الجديد 8766 يتجنب التعارض مع الخدمة القديمة على 8765. لم تُوقف الخدمة القديمة ولم تُعدّل نسخة GuideGlass الأخرى أو VOLTRA.

إيقاف المسح يوقف المعالجة لا خادم الويب. لإيقاف الخادم الذي شغّلته من النافذة اضغط Ctrl+C. إن كان 8766 مستخدمًا، لا تُنهِ عمليات مجهولة؛ استخدم `start_windows.bat --port 8767`.

## التثبيت على Windows آخر

استخدم Python **3.12 64-bit**. من مجلد المشروع:

~~~powershell
.\setup_windows.bat
.\.venv\Scripts\python.exe tools\prepare_assets.py --sample
.\start_windows.bat
~~~

التثبيت الأول يحتاج الإنترنت لتنزيل PyTorch CPU والنماذج وThree.js. تسجيل TUM الحقيقي اختياري وحجمه نحو 0.47 GB قبل استخراج مجموعة محدودة من 150 إطارًا. بعد ذلك يعمل التحليل والعرض محليًا دون API أو مفتاح مدفوع.

إذا فشل التنزيل، يظهر الخطأ ولا يُعرض نجاح وهمي. أعد الخطوة الفاشلة. الملفات المكتملة تُعاد استخدامها.

## الآيفون: العرض مقابل التقاط الكاميرا

- **عرض خريطة كاميرا Windows أو الفيديو** يعمل عبر رابط الشبكة المحلية HTTP، مع Safari حديث يدعم WebGL 2 وimport maps.
- **التقاط صور كاميرا الآيفون** يحتاج HTTPS موثوقًا وإذن الكاميرا، وليس مجرد تغيير http إلى https. هذا شرط [getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).
- لم يُختبر هاتف فعلي أو ميكروفون فعلي في جلسة التطوير. لا تعتبر نجاح اختبارات Python إثباتًا لذلك.
- عند قفل الهاتف أو إخفاء الصفحة، تُوقف الكاميرا والالتقاط. لا تعتمد على الصفحة كخدمة تنبيه تعمل في الخلفية.
- اسمح لـPython في Windows Firewall على الشبكات **Private فقط** إذا منع Windows اتصال هاتفك. لم تُغيّر إعدادات الجدار الناري تلقائيًا.

### HTTPS خاص اختياري عبر Tailscale

لم يُفعّل هذا المسار تلقائيًا ولم تُغيّر إعدادات VOLTRA. إذا كان Windows والآيفون مسجلين بالفعل في شبكتك الخاصة، راجع `tailscale serve status` أولًا واختر منفذ HTTPS غير مستخدم، مثل 8443. بعد التأكد من تقييد الوصول لأجهزتك:

~~~powershell
.\.venv\Scripts\python.exe server.py --host 127.0.0.1 --port 8766 --allow-host YOUR_WINDOWS_NAME.YOUR_TAILNET.ts.net
tailscale serve --https=8443 http://127.0.0.1:8766
~~~

يفتح الهاتف العنوان HTTPS الذي يطبعه Tailscale، مع :8443. أبقِ الأمر في المقدمة لتسهيل إيقافه. لا تستخدم Funnel أو فتح منفذ الراوتر؛ الخدمة لا تملك تسجيل دخول خاصًا بها. لا تستخدم `serve reset` لأنه قد يزيل إعدادات تطبيقاتك الأخرى. [مرجع Serve الرسمي](https://tailscale.com/docs/reference/tailscale-cli/serve).

بديل: شهادة TLS موثوقة لدى الهاتف تطابق عنوان الخادم:

~~~powershell
.\.venv\Scripts\python.exe server.py --tls-cert PATH_TO_CERT.pem --tls-key PATH_TO_KEY.pem --allow-host YOUR_HOSTNAME
~~~

لا تتجاوز تحذيرات الشهادات. إعداد HTTPS والثقة والأذونات يحتاج تجربة على هاتفك.

## مصادر الصور والمعايرة

المصادر: تسجيل RGB-D حقيقي، نفس التسجيل كصور RGB فقط، ملف فيديو، كاميرا Windows (رقم 0–4)، كاميرا المتصفح، وصور ESP32 عبر الجسر الأصلي.

الكاميرا العادية تستخدم معاملات pinhole تقديرية ما لم ترفع ملف JSON معايرة خاصًا بها. مثال **لمعاملات تسجيل TUM فقط، لا تنسخه كمعايرة لكاميرتك**:

~~~json
{
  "width": 640, "height": 480,
  "fx": 525.0, "fy": 525.0,
  "cx": 319.5, "cy": 239.5,
  "calibrated": false,
  "source": "TUM_registered_ROS_defaults",
  "distortion": []
}
~~~

المعاملات تحتاج أن تطابق العدسة والدقة والقص الفعلي. عند تغيير الدقة يصحح البرنامج معاملات الإسقاط. يجب تصحيح تشوه العدسة وتسجيل العمق على RGB مسبقًا؛ قيم distortion غير الصفرية تُرفض في هذه النسخة. لا توجد أداة معايرة عدسة أو مزامنة IMU ضمن هذا الإصدار.

خريطة AI تعتمد Depth Anything V2 Metric Indoor Small. خيارات الدقة 280/392/518، والافتراضي 392. هي تقديرات داخلية تعلمها النموذج؛ لا تستخدمها لقياس مسافة أمان. تغيير الدقة قد يحسن التفاصيل لكنه لا يضمن صحة المقياس.

## ما الذي يعمل وما حدوده؟

- تحويل العمق الفعلي أو المتوقع إلى XYZ وفق معاملات الكاميرا مع ألوان الصورة الأصلية.
- ORB + PnP RANSAC وتحقق إسقاط/اتساق عمق، مع استرجاع محلي من إطارات مرجعية حديثة.
- دمج voxel محدود الذاكرة: 160,000 نقطة محفوظة، حتى 80,000 معروضة. لا يملأ الأسطح غير المرصودة.
- الخريطة تتوقف عن قبول الإطار عند فقدان التتبع، ولا تُثبت الكاميرا اصطناعيًا لتزوير الاستمرارية.
- حفظ NPZ آمن بلا pickle وتصدير PLY؛ إعادة الفتح للعرض فقط. البدء الجديد ينشئ أصل إحداثيات جديدًا.
- الكشف الفعلي SSDLite/COCO عن أشخاص ومركبات وأجسام شائعة. ليس كاشفًا مضمونًا لكل العوائق أو الأرصفة.
- الموقع ثلاثي الأبعاد يظهر فقط عند وجود عمق صالح ومتسق وموضع كاميرا مقبول. عمق AI يظل تقديريًا.
- تُستبعد صناديق الأشخاص والمركبات من الدمج عند تفعيل الكشف، دون استنتاج أنها تتحرك. لا يوجد تقدير سرعة أو خطر متحرك.
- الوجه يعكس Idle / Listening / Analyzing / Warning / Speaking. الأوامر الصوتية الحالية بسيطة: ابدأ/توقف، وليست محادثة LLM.
- تنبيه حساس المسافة له أولوية باللغة العربية. التعرف الصوتي اختياري وقد يستعمل خدمة مزود المتصفح؛ معالجة الصور لا ترفع صورك للسحابة.
- **ليست منظومة SLAM مكتملة**: لا يوجد global loop closure أو bundle adjustment أو Mesh أو تصحيح عالمي للانجراف.
- المسح الحي غير المحفوظ موجود في الذاكرة ويُفقد عند إغلاق الخادم. احفظه قبل البدء بمسح جديد.

## وظائف النظارة الأصلية محفوظة

ضع IP الخاص بـESP32 المتصل بنفس Wi-Fi. الجسر يطلب:

- `http://DEVICE_IP/capture`: صورة JPEG، افتراضيًا المنفذ 80.
- `http://DEVICE_IP:82/distance`: مثل `{"distance_mm":750,"valid":true}` أو `{"distance_cm":75,"valid":true}`.

القراءة المفقودة تظهر — ولا تتحول إلى صفر. عند مسافة صحيحة أقل من متر يصدر التنبيه المحدود التكرار. أزرار الصوت الأربعة القديمة ما زالت **محاكاة معلنة** لا كشف أجسام. Firmware ESP32 غير مرفق ولم يُختبر جهاز فعلي.

## للوصول إلى مقياس حقيقي

يلزم RGB-D أو stereo متزامن ومعاير يعطي عمقًا بالمتر، مع تسجيل RGB/Depth ومعاملات كاميرا صحيحة. مثال مسار توسعة: كاميرا مدعومة من [RealSense SDK](https://github.com/realsenseai/librealsense) مع قارئ عمق مباشر؛ لم يُنفذ برنامج تشغيلها هنا.

هاتف iPhone مجهز بـLiDAR يحتاج عادة جسر iOS أصلي يرسل sceneDepth وconfidenceMap ومعاملات/وضعية ARKit إلى Windows؛ صفحة Safari الحالية تستقبل RGB فقط ولا تمنح LiDAR تلقائيًا. [مثال Apple الرسمي](https://developer.apple.com/documentation/arkit/displaying-a-point-cloud-using-scene-depth).

حساس [VL53L1X](https://www.st.com/en/imaging-and-photonics-solutions/vl53l1x.html) في الجسر الحالي يرسل قراءة مسافة واحدة؛ ليست خريطة عمق لكل بكسل. وحتى RGB-D يحتاج معايرة واختبار دقة على مشاهدك، ولا يضمن مسحًا هندسيًا دقيقًا تلقائيًا.
